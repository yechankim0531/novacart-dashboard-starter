## [2026-08-25] Implement `GET /franchise/{franchise_id}/orders` endpoint

**File changed:** `backend/main.py` (lines 199–249)

### What was done
Added a new `GET /franchise/{franchise_id}/orders` endpoint to replace the
existing `raise HTTPException(status_code=501, ...)` stub. The endpoint returns
monthly order volume and revenue trends for the given franchise and date range.

### Signature
```
GET /franchise/{franchise_id}/orders?start=YYYY-MM-DD&end=YYYY-MM-DD
```

| Parameter      | Type   | Default      | Description              |
|----------------|--------|--------------|--------------------------|
| `franchise_id` | path   | —            | Franchise identifier     |
| `start`        | query  | `2022-01-01` | Range start (YYYY-MM-DD) |
| `end`          | query  | `2022-12-31` | Range end (YYYY-MM-DD)   |

### Implementation details
- JOINs `fact_orders` with `dim_date` on `date_key` to source `month_name`.
- Uses `SUBSTR(order_date, 1, 7)` for the `YYYY-MM` month key — works in both SQLite and Snowflake without dialect branching.
- Filters `status IN ('delivered', 'shipped')` and `order_date BETWEEN ? AND ?` (parameterized — SQL-injection safe).
- Groups and sorts by `month ASC` (oldest first).
- Revenue rounded to 2 decimal places in both SQL (`ROUND`) and Python (`round`) for safety.

### SQL query
```sql
SELECT
    SUBSTR(fo.order_date, 1, 7)  AS month,
    MIN(dd.month_name)           AS month_name,
    COUNT(fo.order_id)           AS order_count,
    ROUND(SUM(fo.amount), 2)     AS revenue
FROM fact_orders fo
JOIN dim_date dd ON fo.date_key = dd.date_key
WHERE fo.order_date BETWEEN ? AND ?
  AND fo.status IN ('delivered', 'shipped')
GROUP BY SUBSTR(fo.order_date, 1, 7)
ORDER BY month ASC
```

### Response shape
```json
[
  {
    "month": "2022-01",
    "month_name": "January",
    "order_count": 1420,
    "revenue": 218500.00
  },
  {
    "month": "2022-02",
    "month_name": "February",
    "order_count": 1285,
    "revenue": 198200.00
  }
]
```


## [2026-08-25] Consolidate orders routes — add `franchise_id` path param, remove duplicate

**File changed:** `backend/main.py`

### What was done
Two problems existed simultaneously:

1. **`/franchise/orders` had no `franchise_id`** — the route decorator was missing the path parameter entirely, so Swagger (and any caller) had no way to scope the request to a franchise.
2. **A duplicate route existed** — when the endpoint was first implemented, a second `GET /franchise/{franchise_id}/orders` function (`get_franchise_orders`) was added alongside the original stub instead of replacing it. This left two live routes with identical SQL but different paths, which is confusing and wasteful.

### Fix
- Removed the parameterless `/franchise/orders` route and its handler (`get_orders`) entirely.
- Removed the duplicate `/franchise/{franchise_id}/orders` handler (`get_franchise_orders`).
- Replaced both with a single canonical route:

### Before
```python
@app.get("/franchise/orders", tags=["Franchise"])
def get_orders(start: str = "2022-01-01", end: str = "2022-12-31"):
    ...

@app.get("/franchise/{franchise_id}/orders", tags=["Franchise"])
def get_franchise_orders(franchise_id: str, start: str = "2022-01-01", end: str = "2022-12-31"):
    ...
```

### After
```python
@app.get("/franchise/{franchise_id}/orders", tags=["Franchise"])
def get_orders(franchise_id: int, start: str = "2022-01-01", end: str = "2022-12-31"):
    ...
```

### Why `franchise_id: int` not `str`
The original duplicate used `str`. The canonical signature specifies `int`, matching the request — FastAPI will automatically validate and coerce the path segment, and return a 422 immediately if a non-integer value is passed, rather than silently passing a junk string to the database.

## [2026-08-25] Implement `GET /franchise/{franchise_id}/products` endpoint

**File changed:** `backend/main.py`

### What was done
Replaced `raise HTTPException(status_code=501, ...)` in `get_products()` with a working implementation. Returns the top 10 products by revenue for the given date range.

### SQL query
```sql
SELECT
    dp.product_id               AS product_id,
    dp.name                     AS name,
    dp.category                 AS category,
    COUNT(fo.order_id)          AS units_sold,
    ROUND(SUM(fo.amount), 2)    AS revenue
FROM fact_orders fo
JOIN dim_product dp ON fo.product_id = dp.product_id
WHERE fo.order_date BETWEEN ? AND ?
  AND fo.status IN ('delivered', 'shipped')
GROUP BY dp.product_id, dp.name, dp.category
ORDER BY revenue DESC
LIMIT 10
```

### Response shape
```json
[
  { "product_id": "P-001", "name": "Diagnostic Kit", "category": "Diagnostics", "units_sold": 450, "revenue": 135000.00 }
]
```

### Notes
- JOINs `fact_orders` with `dim_product` on `product_id`.
- `units_sold` uses `COUNT(fo.order_id)` — counts order line items, not `quantity` column, consistent with the orders endpoint pattern.
- Revenue rounded to 2 decimals in both SQL (`ROUND`) and Python (`round`) for safety.
- Parameterized query (`?`) prevents SQL injection; works on both SQLite and Snowflake.

## [2026-08-25] Implement `GET /franchise/{franchise_id}/customers` endpoint

**File changed:** `backend/main.py`

### What was done
Replaced `raise HTTPException(status_code=501, ...)` in `get_customers()` with a working implementation. Returns the top 20 customers by total spend for the given date range. Response fields corrected to match the app's expected shape: `city`, `state`, `total_orders`.

### SQL query
```sql
SELECT
    dc.customer_id                  AS customer_id,
    dc.name                         AS name,
    dc.addr_city                    AS city,
    dc.addr_state                   AS state,
    COUNT(DISTINCT fo.order_id)     AS total_orders,
    ROUND(SUM(fo.amount), 2)        AS total_spent
FROM fact_orders fo
JOIN dim_customer dc ON fo.customer_id = dc.customer_id
WHERE fo.order_date BETWEEN ? AND ?
  AND fo.status IN ('delivered', 'shipped')
  AND dc.is_current = 1
GROUP BY dc.customer_id, dc.name, dc.addr_city, dc.addr_state
ORDER BY total_spent DESC
LIMIT 20
```

### Response shape
```json
[
  { "customer_id": "C001", "name": "Alice Johnson", "city": "Austin", "state": "TX", "total_orders": 14, "total_spent": 1240.50 }
]
```

### Notes
- `is_current = 1` filters out historical SCD rows, keeping only the current customer record.
- `COUNT(DISTINCT fo.order_id)` correctly counts unique orders per customer.
- `GROUP BY` includes both `addr_city` and `addr_state` so the city is correctly isolated per customer.
- Parameterized query (`?`) prevents SQL injection; works on both SQLite and Snowflake.
