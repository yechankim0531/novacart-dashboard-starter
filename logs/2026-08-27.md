## [2026-08-27] Add `frontend/nginx.conf`

**File changed:** `frontend/nginx.conf` (confirmed existing)

### What was done
Verified that `frontend/nginx.conf` already exists and is correctly configured. The file was not found by glob initially due to a tool limitation, but the file was confirmed present via directory listing.

### Config
```nginx
server {
    listen 3000;
    root /usr/share/nginx/html;
    index index.html;
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

### Why
The `frontend/Dockerfile` has a `COPY nginx.conf /etc/nginx/conf.d/default.conf` step. Without this file the Docker build fails. The `try_files` directive ensures React client-side routing works — any unknown path falls back to `index.html` so the React Router handles it.

## [2026-08-27] Fix Snowflake query parameter format — replace `?` with `%s`

**File changed:** `backend/connection.py` (line 126)

### What was done
Added a single line to `execute_query()` that replaces `?` placeholders with `%s` before executing queries against Snowflake.

### Before
```python
if DATA_BACKEND == "snowflake":
    cursor = conn.cursor(snowflake.connector.DictCursor)
    cursor.execute(query, params)
```

### After
```python
if DATA_BACKEND == "snowflake":
    cursor = conn.cursor(snowflake.connector.DictCursor)
    query = query.replace("?", "%s")
    cursor.execute(query, params)
```

### Why
All SQL queries across the five franchise endpoints use `?` as the parameter placeholder — this is the SQLite convention. Snowflake's Python connector uses `%s` instead. When the app was deployed to SPCS and `DATA_BACKEND=snowflake`, every parameterized query threw:

```
TypeError: not all arguments converted during string formatting
```

Because the Snowflake connector tried to do Python string `%`-formatting on the query but found `?` characters it didn't know how to handle.

The fix is applied at the `execute_query()` layer so all endpoints benefit automatically — no changes needed in the individual route files.

### Diagnosed from
Backend logs retrieved via:
```sql
USE DATABASE NOVACART_DB;
USE SCHEMA APP;
CALL SYSTEM$GET_SERVICE_LOGS('FRONTEND_SERVICE_GROUP1', '0', 'backend', 100);
```
